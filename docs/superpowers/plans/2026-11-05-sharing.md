# Sharing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Invite links, per-token limits, pause/resume, `/v1/me`, MCP and an audit log, so Hashi can be shared safely.

**Architecture:** Policy lives on the token row (SQLite, migrated with `PRAGMA user_version`). Every prompt, from HTTP or MCP, goes through one `api::submit()` that enforces pause, pending and usage caps. Invites are hashed one-time codes that create a token on redeem. Static claim and "my access" pages are compiled into the binary.

**Tech Stack:** Rust 2024, axum 0.8, rusqlite 0.41, ratatui 0.30, time 0.3.

**Spec:** `docs/superpowers/specs/2026-11-05-sharing-design.md`

## Global Constraints

- MSRV 1.89; `unsafe` forbidden; no `unwrap`/`expect` outside tests; `clippy -D warnings` on latest stable.
- No em dash or other banned dashes in any file (see the user's global rules); en dash only in numeric ranges.
- New secrets: invite codes are `hashi_inv_` + 64 hex chars; only SHA-256 stored.
- Day/month windows are UTC. JSON keys camelCase. Error shape `{"error":{"code","message"}}`.
- Existing databases must upgrade in place; existing tests keep passing.

## Review Focus

1. A 0.1.x database (user_version 0) opened by the new binary: migrates, keeps tokens. Test: `store::tests::migrates_v1_database_in_place`.
2. Two concurrent redeems of one invite: exactly one token is created. Test: `store::tests::redeem_is_single_use`.
3. A paused token calling MCP `tools/call`: refused like HTTP. Test: `tests/mcp.rs::paused_token_cannot_call_tools`.
4. Limit reached at exactly the cap (N-th allowed, N+1-th refused). Test: `tests/api.rs::daily_request_cap_is_exact`.
5. Invite created with no public URL: response says `localOnly: true` and the URL is the local one. Test: `tests/api.rs::invite_without_public_url_is_local_only`.
