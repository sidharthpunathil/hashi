## Notes

**What it is.** Tencent CodeBuddy Code (`@tencent-ai/codebuddy-code`), a closed-source Claude Code work-alike from Tencent Cloud. Bins `codebuddy`, `cbc`, `codebuddy-code` (package.json bin). The npm package has no repository URL, so `opensrc fetch` failed ("No repository URL found"); I read the tarball from `npm pack @tencent-ai/codebuddy-code@2.184.0` instead: minified bundle `dist/codebuddy.js` (single-line webpack modules, cited as line:byte offset) plus the English docs it ships under `dist/web-ui/docs/en%2Fcli%2F*.md` (same content as https://www.codebuddy.ai/docs/cli/). Nothing was run; fixtures are derived from source.

**Headless.** `-p/--print` with a commander `[prompt]` positional (dist/codebuddy.js line 1516 @8299214: `.argument("[prompt]","Your prompt")`, `-p, --print`, `--output-format <format>` text|json|stream-json). Commander honours `--`, so `-p --output-format stream-json ... -- <prompt>` is safe. Note the variadic options `--allowedTools <tools...>` / `--disallowedTools <tools...>` (line 1516 @8301189): without `--` they would swallow a following positional prompt.

**Gotcha: subcommand names.** Commander puts args after `--` into operands and still dispatches when operands[0] names a subcommand. Top-level subcommands: agents, auto-mode, cleanup, config, daemon, doctor, mcp, plugin, project, ps, remote-host, sandbox, update. A prompt that is exactly one of these words (for example `update`, which self-updates) would run the subcommand instead of the model. Hashi should refuse or pad such prompts (a trailing space is enough). Derived from commander semantics, UNVERIFIED by running.

**Output: use `stream-json`, not `json`.** `--output-format json` in print mode renders `toSerializableArray()`: a JSON ARRAY of internal history items (OpenAI-agents style `message`/`function_call` items, not Claude shapes) with the result object appended last (dist/codebuddy.js line 1561 @8528633, LLMView.render / toSerializableArray). That differs from Claude Code's single result object. Worse, when the run stops on a permission interruption the same view prints a plain-text "Interruption reason: Needs approval ..." message even in json mode (same location). `stream-json` is JSONL: `system/init` (dist/codebuddy.js line 1477 @7950311: `{type:"system",subtype:"init",uuid,session_id,apiKeySource,cwd,tools,mcp_servers,model,permissionMode,slash_commands,output_style}`), Claude-shaped `assistant`/`user` frames (`convertToClaudeStreamEvent`), `system/usage_update` stage and snapshot events (docs stream-json-turn-usage.md), background `system/task_*` events (docs headless.md:98-138) and a terminal `result`. No `--verbose` requirement was found (unlike Claude Code).

**Result object vs Claude Code.** Built in `createResultMessage` (dist/codebuddy.js line 1599 @8708987). Success: `{type:"result",subtype:"success",is_error:false,result,uuid,session_id,duration_ms,duration_api_ms,num_turns,total_cost_usd:0,usage{input_tokens,output_tokens,cache_creation_input_tokens,cache_read_input_tokens,cache_creation:null,server_tool_use:null,service_tier:null},permission_denials,structured_output?}`, then enriched with `modelUsage` and `_meta` (context usage) (line 1601 @8732101). So it matches Claude Code's result shape and Hashi's `claude_result` parser, with three differences: (1) `total_cost_usd` is hard-coded `0` (credits are never put there, docs stream-json-turn-usage.md TL;DR 4), so Hashi should treat cost as unknown rather than 0; (2) the error result (`subtype:"error_during_execution"`, `is_error:true`) has NO `result` field; the message is in `errors: [string]` plus optional `errors_info` (`buildErrorTerminalFields`, same location). Hashi's `claude::parse_output` falls back to the subtype, so the reported message would be just `error_during_execution` unless it also reads `/errors/0`; (3) `usage` is session-cumulative (docs stream-json-turn-usage.md TL;DR 4), so after `--resume` it likely includes earlier turns (UNVERIFIED); per-turn usage is in `result._meta["codebuddy.ai/turnUsage"].total.usage`. Cancelled runs report `subtype:"success"`, `result:""` plus `terminal_reason` (`createCancelledResultMessage`). Failures before the agent loop starts (bad auth, bad flags) probably go to stderr as text with no result line (UNVERIFIED).

**Session.** `session_id` on every frame. `-r, --resume [sessionId]` (optional value), `-c/--continue`, `--session-id <id>` pre-assigns an id (letters, digits, `-_:`; must start with letter or digit) (line 1516 @8303461), `--fork-session`, `--no-session-persistence`. Docs use UUIDs (headless.md:55).

**Model.** `--model <id>` (model ID, for example `gpt-5`, aliases accepted per docs cli-reference.md:116); `CODEBUDDY_MODEL` env; `--fallback-model` (print only).

**Permissions headless.** Modes: default, acceptEdits, auto, dontAsk, plan, bypassPermissions (+ fullAccess from IDE clients). In `-p`, default/acceptEdits/plan deny anything that would ask; `dontAsk` turns every ask into deny, including AskUserQuestion/ExitPlanMode; `auto` sends asks to an AI reviewer (docs permission-modes.md:472-486, 268-287). Reads inside the cwd (trusted by default) are allowed; Edit/Bash need rules (permissions.md:28, 243). `-y/--dangerously-skip-permissions` = bypassPermissions but HIGH/CRITICAL commands still ask unless `CODEBUDDY_IS_SANDBOX=1` is in the process env (cli-reference.md:125, 146-148). Safe default: pin `--permission-mode dontAsk` and never pass `-y` or `CODEBUDDY_IS_SANDBOX`. `--settings` (JSON string) and `--allowedTools` can grant tools, so strip them from operator args. A workspace `.codebuddy/settings.json` is an untrusted source and cannot bypass command safety checks (permissions.md:17, 24). `--permission-prompt-tool` is documented as not supported (headless.md:40-42).

**Auth.** Priority `CODEBUDDY_AUTH_TOKEN` > `apiKeyHelper` > `CODEBUDDY_API_KEY` (docs iam.md:18). `CODEBUDDY_API_KEY` is always used in `-p` (env-vars.md:13); with an API key, `CODEBUDDY_INTERNET_ENVIRONMENT` must match the account's edition: unset = international (www.codebuddy.ai), `internal` = China (copilot.tencent.com / www.codebuddy.cn), `ioa`, `cloudhosted`, `selfhosted` (iam.md:96-123; product.json endpoints). `CODEBUDDY_BASE_URL` + `CODEBUDDY_API_KEY` + `CODEBUDDY_MODEL` points it at any Anthropic-compatible endpoint (env-vars.md:404-430). Interactive login: start `codebuddy` in a terminal and pick a login method (browser); there is no `login` subcommand. Login state is a file at `<os.homedir()>/Library/Application Support/CodeBuddyExtension/Data/Public/auth/<authId>.info` on macOS (`~/.local/share/CodeBuddyExtension/...` on Linux, `AppData/Local/CodeBuddyExtension` on Windows), shared with the IDE extension (dist/codebuddy.js line 1515 @8217006 and line 7215 @23385637 FilePathServiceImpl.getBasePath). `CODEBUDDY_CONFIG_DIR` relocates `~/.codebuddy` (settings, sessions, plugins, mods; line 7215 @23439567 and many others) but NOT that auth file, so `config_dir_env` is null: only overriding `HOME` relocates everything. `CODEBUDDY_CREDENTIALS_IN_MEMORY=1` keeps credentials in memory. Docs also mention OS keychain storage (iam.md:413-421); the bundle code I read uses the file store, keychain use UNVERIFIED.

**Limits.** Retry/limit classifier regexes (dist/codebuddy.js line 5378 @19101957): overload(ed), rate limit(ed| exceeded), too many requests, quota (exhausted|exceeded), (no available|insufficient) credit(s), credit(s) exhausted, capacity exceeded, and Chinese 额度已用尽 / 额度不足 / 请求限流; business code `200429`. Localised quota texts at line 5248 @15896216 ("The account quota is exhausted.", "Your personal quota is used up ...", "The current usage limit does not allow this request.").

**Env.** `DISABLE_AUTOUPDATER=1`, `DISABLE_TELEMETRY=1`, `DISABLE_ERROR_REPORTING=1` (env-vars.md:236-243); `CODEBUDDY_CODE_DISABLE_BACKGROUND_TASKS=1` hides `run_in_background` so no task events arrive after the result (headless.md:138; the SDK sets it for single-shot `query()`). Never set `CODEBUDDY_IS_SANDBOX`. Stdin: non-TTY stdin is read as extra input (headless.md:173-175); `/dev/null` should be harmless (UNVERIFIED). Slash commands in a `-p` prompt: assumed to run like Claude Code (UNVERIFIED). Exit codes: not documented (UNVERIFIED). Node >= 18.20.8 (bin/codebuddy). Not a git repo: fine (worktree features only need git). Install also via `brew install Tencent-CodeBuddy/tap/codebuddy-code` or `curl -fsSL https://www.codebuddy.cn/cli/install.sh | bash` (installation.md:16-101).

## Hashi features (coverage pass, 2026-11-16)

- **Login accounts:** no. The login is the file <base>/Data/Public/auth/<authId>.info where <base> is os.homedir()+'Library/Application Support/CodeBuddyExtension' (macOS), 'AppData/Local/CodeBuddyExtension' (Windows) or '.local/share/CodeBuddyExtension' (Linux) (dist/codebuddy.js line 1515 @8216785 getAuthSavePath; line 7215 @23385641 FilePathServiceImpl.getBasePath/sharedDataPath). Nothing but HOME moves it: CODEBUDDY_CONFIG_DIR only moves ~/.codebuddy (settings, sessions). So the only working dir_var would be HOME, which also moves git, ssh and npm config; and the file is shared with the CodeBuddy IDE extension. CODEBUDDY_CREDENTIALS_IN_MEMORY=1 keeps the session in memory only (line 1515 @8206628), which does not persist a second login. The docs claim Keychain / keyring / Credential Manager storage (docs en/cli/iam.md 'Credential Management'), but the bundle writes a JSON file; token fields are encrypted at rest only when a WorkBuddy host bootstraps a key (line 7215 @23382001 createCredentialFieldCodec, default policy 'off'; line 1599 @8715739 configureManagedCredentialProtection).
- **API-key accounts:** yes. In -p the API key is always used (docs en/cli/env-vars.md:12) and a stored login does not outrank it. Priority is CODEBUDDY_AUTH_TOKEN > apiKeyHelper > CODEBUDDY_API_KEY (docs en/cli/iam.md:18): Hashi already strips CODEBUDDY_AUTH_TOKEN, but an apiKeyHelper in the owner's ~/.codebuddy/settings.json would still win, and CODEBUDDY_INTERNET_ENVIRONMENT must match the key's edition (iam.md:96-123).
- **Status check:** {"args": null, "signed_in_when": null}
- **Identity:** {"file": "Library/Application Support/CodeBuddyExtension/Data/Public/auth/Tencent-Cloud.coding-copilot.info", "pointer": "/account/nickname", "jwt_claim": null}
- **Switch:** no. The login is one plain JSON file (session {auth:{accessToken,refreshToken,expiresAt,domain},account:{uid,nickname,...}}) so a copy would work, but: (1) there is no dir_var other than HOME, so Hashi has no account folder to copy from; (2) live_dir is per platform (macOS shown; Linux '.local/share/CodeBuddyExtension/Data/Public/auth', Windows 'AppData/Local/CodeBuddyExtension/Data/Public/auth'), and Switch has one live_dir; (3) the file name is the product auth id, and resolveCustomAuthId appends '-<x>-<binaryName or endpoint host>' for branded/custom endpoints (line 1515 @8217032; module 290780 resolveCustomAuthId), and the China edition uses another product.json; (4) the file is also read and watched by the CodeBuddy IDE extension and CLI (line 1515 @8209772 initializeWatcher), and a logout writes a marker next to it. The file name and pointers are from the bundle, unverified by running.
- **Live quota:** no. No quota or credit endpoint or command found in the bundle or docs. /cost and /stats report session tokens only (docs en/cli/costs.md:9-14, en/cli/slash-commands.md:26,52), and total_cost_usd is always 0 (docs en/cli/stream-json-turn-usage.md TL;DR 4).
