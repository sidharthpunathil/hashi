## Notes

**What it is.** **Qoder CLI CN**, the China-region build of Alibaba's Qoder CLI. It is the **same bundle** as `@qoder-ai/qodercli` with a build-time site constant switched to `cn`: the brand table in `bundle/qodercli.js` (offset ~1836) maps `cn` to `CLI_BRAND_CLI_BIN:"qoderclicn"`, `CLI_BRAND_ENV_PREFIX:"QODERCN_"`, user dir `.qoder-cn`, endpoints `gateway.qoder.com.cn` / `openapi.qoder.com.cn`, docs `docs.qoder.cn`, keychain service `qoderclicn-login` (offset ~32097617). The global build hard-codes `"cn"==(fUa="global")` (offset ~19838). npm `@qodercn-ai/qoderclicn` 1.1.89 ships bins `qoderclicn` (bundle) and `qodercn` (dispatcher); the native installer installs `qodercn` (https://docs.qoder.cn/cli/installation.md). Everything in the `qoder` spec applies, with the env prefix `QODERCN_` instead of `QODER_`; the CN tarball itself was not unpacked, so CN-specific details are inferred from the shared bundle (UNVERIFIED in detail). Accounts and PATs are separate from the global site.

**CN specifics.** PAT env `QODERCN_PERSONAL_ACCESS_TOKEN` (https://docs.qoder.cn/cli/authentication.md, lines 35, 79-98); config root `~/.qoder-cn`, overridden by `QODERCN_CONFIG_DIR`, then `QODERCN_CLI_HOME` + dir name, `QODERCN_CONFIG_DIR_NAME` (package README "配置目录环境变量"). `QODERCN_SERVICE_ACCOUNT_KEY` / `QODERCN_JOB_TOKEN` are inferred from the `yi("SERVICE_ACCOUNT_KEY")`/`yi("JOB_TOKEN")` prefixed env helpers (UNVERIFIED). Project resources still use `<cwd>/.qoder`.

**Shared behaviour (see qoder.json for full citations).** Claude Code clone (commander, minified/obfuscated). Headless `-p/--print`, `-o/--output-format text|json|stream-json`; `json` prints one Claude Code-style result object `{type:"result", subtype, is_error, result, session_id, usage{input_tokens,output_tokens,...}, total_cost_usd (always 0), total_credits, modelUsage, permission_denials, ...}`; error results carry `errors[]`, `error_message`, `error_code` and no `result`. `--` separates the prompt. Resume `-r/--resume <id>`, `--session-id`, `-c/--continue`. Model `-m/--model` (auto, lite, performance, BYOK key). Headless denies anything needing confirmation unless `--permission-mode accept_edits|bypass_permissions` or `--yolo`. Leading `/` runs slash commands. Native installs auto-update unless `general.enableAutoUpdate` is false in settings.

## Hashi features (coverage pass, 2026-11-16)

- **Login accounts:** yes. The config root is --config-dir > QODERCN_CONFIG_DIR > (QODERCN_CLI_HOME or homedir)/.qoder-cn (function Pi, bundle (offsets in the decoded global bundle; the CN bundle has the same functions at nearby offsets) ~3304000 region; resolver PWs at ~31811000). The login store is <root>/.auth/user, encrypted with a key tied to <root>/.auth/machine_id, with a lock file <root>/.auth/.credential-transaction (module nW: oee=join(DBi(),".auth"), ZSe=machine_id, KSe=.credential-transaction, ~3313738; xWA() returns .auth/user for prod, .auth/user.<env> otherwise, ~3304393). DBi() only diverts it when QODER_SDK_AUTH_PAYLOAD_FILE and QODER_SDK_AUTH_CONFIG_DIR are set (~3303636). The keytar Keychain code (~21987716, service class UEA) is only used for MCP server OAuth tokens (class S6e sanitizeServerName, ~21988505), not the Qoder login. So QODERCN_CONFIG_DIR alone isolates a login.
- **API-key accounts:** yes. A PAT in env is used instead of the stored login (docs authentication.md; auth flow at ~34236977 reads process.env[QODERCN_PAT] first, then QODERCN_PERSONAL_ACCESS_TOKEN). Caveat: QODERCN_PAT takes precedence over QODERCN_PERSONAL_ACCESS_TOKEN, so an owner's QODERCN_PAT left in the environment would outrank the account's key unless Hashi strips it.
- **Status check:** {"args": ["--list-models"], "signed_in_when": "exit 0"}
- **Identity:** {"file": null, "pointer": null, "jwt_claim": null}
- **Switch:** no. The login is plain files in one folder that the dir_var moves, so copying works in principle, and both files must travel together because .auth/user is encrypted with a key derived from .auth/machine_id (load path decrypts, stage 'decrypt', ~3309000-3322000). Blockers: (1) the file is encrypted, so no expiry pointer can be read and Hashi cannot tell a fresher token from an older one; tokens refresh about every 30 minutes and refresh tokens rotate (rotateCredentialTokens ~18333499), so copying an older copy back can sign the account out; (2) a running qodercli caches the machine id and throws MachineIdChangedError ('The machine ID changed after it was loaded by this process') if it changes under it (kdA/P6, ~3308847); (3) writes are guarded by .auth/.credential-transaction(.lock), which Hashi would have to honour. Feasible only with an mtime-based freshness check and no qodercli running.
- **Live quota:** no. The endpoint exists, but the bearer token is inside the encrypted .auth/user, so Hashi cannot call it without reimplementing the decryption; the interactive /usage and /status panels are TUI-only. Whether a PAT is accepted directly as the bearer is unverified (the CLI exchanges a PAT for a token first, loginWithPAT ~18310996).
- **Usage in output:** tokens
- **Limit messages:** Spec strings cover 'User quota exhausted', 'Rate limited', 'Access limit or rate limit reached' and error_code quota_exhausted/rate_limited. Missing user-facing texts found in the bundle: 'Credits exhausted. Use /usage for details or /upgrade for more.', 'The usage limit has been reached. Please check your quota and try again later.', 'The free plan usage limit has been reached.', 'The free usage limit for this model has been reached.', 'You have reached the daily usage limit.', 'You have exhausted your daily quota on this model.', 'Your Billing Group has reached its Credits limit for this billing cycle.', 'Your team member Credits limit has been reached.'. Suggest adding: 'credits exhausted', 'usage limit has been reached', 'daily usage limit', 'daily quota', 'credits limit'.

Run `qoderclicn login` to authenticate.' and exits 1 when unauthenticated, exit 0 otherwise (~31810188); it can also exit 0 with only BYOK models configured, so treat it as a login check only when no BYOK providers are set.
