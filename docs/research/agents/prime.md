## Notes

Prime Agent is Prime Intellect's open-source (MIT) terminal coding agent, an "RLM harness": the only model tool is a persistent IPython kernel (`python_repl`) through which the model edits files, runs shell commands and spawns subagents (`rlm.spawn`). Repo github:PrimeIntellect-ai/prime-agent (source read at ~/.opensrc/repos/github.com/PrimeIntellect-ai/prime-agent/main/, version 0.10.3, CHANGELOG 2026-11-11). Since 0.10.x it is a Rust rewrite (crates/pa-*) of an earlier TypeScript fork of the Pi coding agent (badlogic pi-mono); the JSON wire format keeps Pi's shape. Not on npm, crates.io, PyPI or Homebrew; installed with `curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh` (README.md:41-55), which also runs `prime-agent --prime-agent-bootstrap` to prepare the Python venv (pa-cli/src/lib.rs:106-109). Not installed here, nothing was run: fixtures are derived from source.

**Headless:** `--mode json` (or `-p/--print` for text) runs the prompts and exits (crates/pa-cli/src/args.rs:260-269, 320-329). Mode resolution: `--mode json` always gives JSON print mode; without `--mode`, a non-TTY stdin also selects text print mode (pa-cli/src/mode.rs:22-36), so under Hashi it is never interactive. Print mode runs in process (pa-cli/src/print_runtime.rs:1513-1858), not through the background daemon.

**Prompt:** hand-written parser honours `--`: everything after it is a message (args.rs:231-239, test args.rs:559-560). Without `--`, a word starting with `@` is read as a file attachment and `-x` is "Unknown option". Each message after `--` is a separate prompt turn (print_runtime.rs:1620-1624), so pass the prompt as ONE argv element. Public subcommands (`agents`, `attach`, `status`, `config`, `session`, ...) are matched only on argv[0] (pa-cli/src/public_command.rs:101-115, lib.rs:119), so base_args starting with `--mode` avoid misrouting. Piped stdin is read with an idle timeout and prepended (lib.rs:233-244, piped_stdin.rs); /dev/null is harmless. A prompt starting with `/` is classified as a session command (`/goal`, `/refine`, `/autonomous`, prompt templates) and never reaches the model (print_runtime.rs:1625-1660).

**Output (`--mode json`)**: JSONL. First line is the session header `{"type":"session","version","id","timestamp","cwd","parentSession"?}` (print_runtime.rs:1075-1110, printed at 1563-1566); then Pi agent events (pa-core/src/session_engine/session_events.rs:119-203): `agent_start`, `turn_start`, `message_start`/`message_end` {message}, `message_update` {message, assistantMessageEvent:{type:text_start|text_delta|text_end|thinking_*|toolcall_*, contentIndex, delta|content}} (session_events.rs:14-80), `tool_execution_start|progress|update|end`, `turn_end` {message (assistant), toolResults}, `agent_end` {messages}; plus `goal_update`, `session_action_update` (pa-cli/src/print_goal.rs:172,186), `compaction_start|compaction_end` and `error` {message:string} (pa-cli/src/print_boundary/events.rs:12-100). Assistant message shape (pa-types/src/ai/mod.rs:522-546): `content[]` blocks (`text`, `thinking`, `toolCall`), `usage{input,output,cacheRead,cacheWrite,totalTokens,cost{input,output,cacheRead,cacheWrite,total}}` (mod.rs:411-432), `stopReason` stop|length|toolUse|error|aborted, `errorMessage?`.

**Parser choice:** text = `assistantMessageEvent.content` of `message_update` events, keep last: the final `text_end` carries the whole final text block. `thinking_end` also has a `content` field (session_events.rs:52-60), harmless because the final text block ends after it; UNVERIFIED for every provider that `text_end` is always emitted. Session id = top-level `/id`, present only on the header line (no other event has a top-level `id`). Usage = sum over `turn_end` of `message.usage.input`/`output`, cost `message.usage.cost.total` (USD, from the model catalog). Pi convention: `input` EXCLUDES cache reads/writes (`cacheRead`, `cacheWrite` are separate), so Hashi under-counts input versus the Claude convention unless it adds them.

**Failure detection gap:** in JSON mode the exit code is always 0 except autonomous gate failures (print_runtime.rs:1810-1856). A provider failure is NOT an `error` event: it is an assistant message with `stopReason:"error"` and `errorMessage` (headless.rs:49-63 is only used in text mode). With the spec below such a run has no `text_end`, so Hashi gets Parse("no answer in output") rather than Reported; a partial answer before a mid-stream failure would be taken as success. Hashi would need a per-event failure pointer (`/message/stopReason` == "error", message `/message/errorMessage` on `turn_end`) to do better. Alternative: `-p` text mode prints only the selected answer to stdout and, on error, `errorMessage` to stderr with exit 1, but gives no session id or usage. Arg/startup errors print `Error: ...` to stderr with exit 1 (lib.rs:77-85, 121-136).

**Resume:** `-r/--resume <id|path>` (args.rs:274-286); id is a UUID v4 (pa-core/src/session/mod.rs:175). Resume resolves within the cwd's session directory; a session from another cwd fails with "belongs to a different project" (print_runtime.rs:1266-1285), so the per-token workspace must be stable. Bare `--resume` errors headless (lib.rs:152-156). `-c` continues the newest session for the cwd. `--no-session` disables persistence (then no header line, UNVERIFIED). Sessions are JSONL files under `<agent dir>/sessions` unless `PRIME_AGENT_SESSION_DIR`/`--session-dir`.

**Model:** `--model <id>` (optionally with `--provider`), `--thinking <level>`, `--models a,b` (args.rs:287-319). Model id syntax (`provider/model` vs bare) UNVERIFIED.

**Permissions:** there is no approval system at all: every model action goes through the Python kernel with the user's permissions, and the README says the worker and kernel processes are not a security sandbox (README.md:111). So auto_approves_tools_headless is true and there is no read-only flag; run it only inside an external sandbox. `--autonomous`/`--goal` keep the run going for more turns and `--autonomous-gate <cmd>` runs a shell command as a quality gate (args.rs:365-422), so they are listed as unsafe. Pinned `--no-skills` stops user Python skills from being imported into the kernel and `--no-prompt-templates` stops `/name` template expansion (args.rs:361-362).

**Process model (UNVERIFIED):** each run starts a Python kernel/worker subprocess (prime-agent-runtime); whether Hashi's kill_on_drop (SIGKILL of the parent only) orphans it was not checked. Requires the venv from the installer bootstrap.

**Config and credentials:** state dir `~/.prime/agent` (pa-cli/src/config.rs:7), relocated by `PRIME_AGENT_CODING_AGENT_DIR` (config.rs:9), which holds `auth.json` (OAuth logins for Claude/ChatGPT/Copilot and saved keys, per pa-daemon tests), settings, models.json and sessions. Login is interactive only: `/login` inside the TUI (README.md Getting Started); no `login` subcommand found. Env API keys per provider (pa-ai/src/env_api_keys.rs:8-38): ANTHROPIC_OAUTH_TOKEN, ANTHROPIC_API_KEY, OPENAI_API_KEY, PRIME_API_KEY (Prime Intellect inference, base URL PRIME_AGENT_INFERENCE_API_BASE_URL), GEMINI_API_KEY, OPENROUTER_API_KEY, COPILOT_GITHUB_TOKEN/GH_TOKEN/GITHUB_TOKEN, plus Bedrock/Vertex env (env_api_keys.rs:77-103) and many others; `--api-key` also exists (avoid: it puts the key on argv). Which provider is the default when several are configured is UNVERIFIED; pass `--model`.

**Env:** telemetry is on by default (pseudonymous metrics); `PRIME_AGENT_TELEMETRY=0` or `DO_NOT_TRACK=1` disables it (pa-cli/src/telemetry_notice.rs:23, mode.rs:295). `PI_OFFLINE=1`/`--offline` also disables telemetry and other network extras (mode.rs:317-346) but its effect on model catalog fetches is UNVERIFIED, so it is not pinned. `NODE_EXTRA_CA_CERTS` is honoured for custom CAs. No update check observed in print mode (UNVERIFIED).

**Limits:** stream failures are classified (pa-ai/src/utils_inner/stream_failure.rs:458-475, 552-555): "Provider rate limit exceeded" for 429 or types matching rate_limit|usage_limit|usage_not_included|throttl, "Provider overloaded"; ChatGPT subscription: "You have hit your ChatGPT usage limit" (pa-ai/src/providers/openai_codex_responses/errors.rs:296). Exact final errorMessage composition (prefix plus provider text) UNVERIFIED; the error fixture text is illustrative.

**Git repo:** not required (works in the current directory, README Getting Started). **Windows:** official x64 build via install.ps1.
